# P1: Project Proposal  

Phase 1 focuses on preparing a **Project Proposal**, which serves as the foundation for all subsequent database design and development phases.

## Guidelines

The **Guidelines** section outlines what students are expected to analyse, document, and plan before any database is designed or implemented. The emphasis is on understanding the **problem domain**, identifying **user requirements**, and proposing a **feasible database solution**.


### Task Deliverables

| No | Task | Description |
|----|------|-------------|
| 1 | Problem Background | - Organizational background study<br>- Benefits of the system / contribution<br>- Project overview<br>- Problem statement<br>- Proposed solutions<br>- Objectives<br>- Scope |
| 2 | System Boundaries | - What will be included<br>- What will not be included<br>- Boundaries of database application<br>- Major user views |
| 3 | Project Plan | - Time to produce the system<br>- Team members involved<br>- Expected completion date<br>- Work Breakdown Structure (WBS)<br>- Gantt Chart |
| 4 | User View Analysis | - Description of data currently held in the database<br>- How the data is used |
| 5 | Database Requirements | - Current or proposed business rules (based on SAD)<br>- Data requirements for stored information<br>- Transaction requirements (insert, update, delete, query) |
| 6 | User View Management | - Description of how user views are managed in the current database system |

## Proposal Structure

The project proposal **must include** the following sections:

1. **Introduction**  
2. **Background Study**  
3. **Problem Statement**  
4. **Proposed Solutions** (include feasibility study)  
5. **Objectives**  
6. **Scope**  
7. **Project Planning**  
   - 7.1 Human Resource  
   - 7.2 Work Breakdown Structure (WBS)  
   - 7.3 Gantt Chart  
8. **Requirement Analysis** (AS-IS analysis)  
   - 8.1 Current Business Process (scenarios, workflow)  
9. **Transaction Requirements**  
   - Data entry  
   - Data update/delete  
   - Data queries  
10. **Benefits and Summary of Proposed System**  
11. **Summary**

## Assessment Rubrics

### 1. Project Proposal

#### Criteria: Content Organization & Issue Explanation

| Level | Description |
|------|-------------|
| **High (4)** | Clearly identifies and explains main issues and their relationships |
| **Average (3)** | Identifies main issues but lacks explanation |
| **Low (2)** | Issues identified but poorly explained |
| **Unsatisfied (1)** | Fails to identify or explain issues |

#### Criteria: Organization Structure

| Level | Description |
|------|-------------|
| **High (4)** | Well-structured with clear introduction, body, and conclusion |
| **Average (3)** | Logical flow but sequence could be improved |
| **Low (2)** | Weak organization with abrupt transitions |
| **Unsatisfied (1)** | Poor organization and illogical flow |

#### Criteria: Content Development & Writing

| Level | Description |
|------|-------------|
| **High (4)** | Accurate, clear, well-supported with examples |
| **Average (3)** | Generally accurate with minor weaknesses |
| **Low (2)** | Vague, loosely related, limited support |
| **Unsatisfied (1)** | Unclear, off-topic, poorly developed |

#### Criteria: Language & Mechanics

| Level | Description |
|------|-------------|
| **High (4)** | No major grammatical or spelling errors |
| **Average (3)** | Minor errors present |
| **Low (2)** | Several major errors |
| **Unsatisfied (1)** | Serious and persistent errors |

#### Criteria: System Boundaries

| Level | Description |
|------|-------------|
| **High (4)** | Complete and accurate scope, boundaries, and user views |
| **Average (3)** | Partial description with minimal errors |
| **Low (2)** | Minimal description with major errors |
| **Unsatisfied (1)** | No clear scope or user views |

#### Criteria: Project Plan

| Level | Description |
|------|-------------|
| **High (4)** | Clear, complete tasks with logical time allocation |
| **Average (3)** | Fairly complete and acceptable timeline |
| **Low (2)** | Vague tasks and weak timeline |
| **Unsatisfied (1)** | Unclear, illogical, unacceptable plan |

### 2. Database Requirements

#### Criteria: Business Rule Interpretation

| Level | Description |
|------|-------------|
| **High (4)** | Correct interpretation with clear entities, attributes, relationships |
| **Average (3)** | Mostly correct with good ideas |
| **Low (2)** | Inaccurate interpretation |
| **Unsatisfied (1)** | No understanding shown |

#### Criteria: Data Requirements

| Level | Description |
|------|-------------|
| **High (4)** | Accurate naming and suitable data types |
| **Average (3)** | Minor errors in naming or data types |
| **Low (2)** | Inaccurate names and unsuitable data types |
| **Unsatisfied (1)** | No understanding of data requirements |

#### Criteria: Transaction Requirements

| Level | Description |
|------|-------------|
| **High (4)** | Accurate and suitable transaction requirements |
| **Average (3)** | Minor errors in transaction requirements |
| **Low (2)** | Inaccurate transaction requirements |
| **Unsatisfied (1)** | Wrong or missing transaction requirements |
